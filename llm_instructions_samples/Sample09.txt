- Validate login theme asset IDs/keys.
- Do not allow custom CSS to escape intended login-theme scope if the current architecture has a safe scoping pattern.
- Preserve brute-force mitigation:
  - username stage first
  - password stage second
  - rate-limit / lockout / retry behavior must not regress if present
  - do not add a single combined username/password form if the source already expects staged login

## 5. Large text-file load performance

Large text files still take too long. Analyze and improve performance. The chunk size likely needs to be increased, but must be increased safely.

### Current constraints

- The viewer must not request the whole file for large files.
- Do not set WebSocket chunk size so high that it causes socket timeout, MAXSTRING, JSON payload, or browser memory errors.
- Chunk size and virtualization threshold must remain separate config values:
  - threshold decides when virtual chunk mode begins
  - chunk size decides each request size
- Large files must not auto-load forever while idle.
- Duplicate chunk requests must be deduped by file id + offset + size.
- No infinite retry loop after chunk failure.
- Save must clear stale caches and reload/revalidate the current view.
- No full-file `/api/mioos/fs/blob` fallback for large text.
- Scrollbar must map to byte offsets smoothly.

### Required performance approach

Analyze source/runtime constraints first, then improve safely:

- Measure or inspect existing chunk sizes and thresholds.
- Identify current WebSocket timeout and request timeout behavior.
- Identify whether HTTP range/text-chunk fallback exists and is safer for larger chunks.
- Prefer increasing HTTP chunk size over WebSocket chunk size if WebSocket is fragile.
- Consider bounded parallel prefetch only if:
  - capped concurrency
  - capped total bytes
  - deduped
  - no idle infinite loop
  - failures stop or degrade gracefully
- Improve initial load:
  - load first visible chunk only
  - optionally prefetch adjacent chunk once
  - avoid rendering giant DOM
- Improve jump-to-middle/end:
  - map scrollbar to byte offset
  - fetch only needed chunk/range
  - cancel/ignore stale responses
- Improve CodeMirror use:
  - use CodeMirror for small/medium full-document editing
  - large text should remain virtual/read-only unless safe chunk-aware editing is implemented
- Do not pretend large random-access editing is supported if unsafe.

### Tests to add

- chunk size and threshold are separate
- chunk size clamp remains MAXSTRING-safe
- no full-file blob fallback for large text
- no idle load loop
- no infinite retry loop
- dedupe by id/offset/size
- jump-to-offset maps to byte range
- stale chunk response ignored
- save clears cache/revalidates
- large file opens initial range only
- adjacent prefetch bounded if implemented
- WebSocket chunk size remains lower than safe ceiling
- HTTP text chunk fallback returns only requested range if implemented
- MAXSTRING boundary synthetic test
- long line chunk boundary test
